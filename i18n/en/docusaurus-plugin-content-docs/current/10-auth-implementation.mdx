# Implement Authentication

## Goal

Add authentication to Bookmark Demo so only signed-in users can use the bookmark features.

This chapter is designed as material for an IDE review. Use an AI coding agent to implement the feature in small, reviewable steps: database migration, server-side auth helpers, auth API routes, protected bookmark routes, UI changes, and tests.

## Feature Scope

Implement email and password authentication with server-side sessions.

- Store password hashes, never plaintext passwords.
- Store a hash of the session token in the database, not the raw token.
- Send the raw session token to the browser in an HTTP-only cookie.
- Add signup, login, logout, and current-user APIs.
- Return `401 Unauthorized` from bookmark APIs when the user is not signed in.
- Keep the existing bookmark behavior unchanged for signed-in users.

This is a local learning exercise, not a complete production authentication system.

## AI Coding Agent Prompt

Use the following prompt as the starting point, then split the implementation into smaller steps if the agent produces too much code at once.

```prompt
This is a local bookmark app built with Node.js, Hono, React, SQLite, and Vitest.
Add email/password authentication using HTTP-only cookie sessions.

Requirements:
- Add a migration that creates users and sessions tables.
- Hash passwords with Node.js crypto.scrypt.
- Generate random session tokens with crypto.randomBytes.
- Store only a SHA-256 hash of the session token in SQLite.
- Set the browser cookie as bookmark_session with HttpOnly, SameSite=Lax, Path=/, and Expires.
- Add POST /api/auth/signup, POST /api/auth/login, POST /api/auth/logout, and GET /api/auth/me.
- Protect GET/POST/PUT/DELETE /api/bookmarks so unauthenticated requests return 401.
- Add a login/signup UI before the bookmark list.
- Add logout UI when signed in.
- Use credentials: "include" for fetch calls that need cookies.
- Add focused Vitest coverage for auth helpers, auth APIs, protected bookmark APIs, and the React auth flow.

Follow the existing code style and test patterns. Keep the change reviewable and avoid unrelated refactors.
```

## Verify

Run the build and test suite.

```bash
npm run build
npm test
```

Then start the local app and verify the behavior in the browser.

```bash
npm run dev
```

Confirm that the app starts on the login screen, signup works, login works, bookmarks are usable after login, and logout returns to the login screen.
