# IDEレビューを体験する

## この章の目的

[VS Code機能拡張のセットアップ](vscode-extension-setup)で入れたCodeRabbit拡張を使い、PRを作る前にIDE上でレビューを受ける流れを体験します。

[前章の認証機能の実装](auth-implementation)を行ってから開始してください。この章では、その変更を題材にして、CodeRabbitがどのような指摘を出すか、指摘をどう読み、どう対応するかを確認します。

## IDEレビューを開始する

[VS Code機能拡張のセットアップ](vscode-extension-setup)でインストールしたCodeRabbit拡張を使います。拡張は、VS Codeの拡張機能画面で `CodeRabbit` と検索するか、[Visual Studio Marketplace](https://marketplace.visualstudio.com/items?itemName=CodeRabbit.coderabbit-vscode)からインストールできます。

VS Codeの左側にあるCodeRabbitアイコンをクリックし、CodeRabbitのサイドバーを開きます。

サイドバーの Reviews タブを開き、Review all changes ボタンを押します。これで、現在の作業ツリーにある変更全体に対するレビューが始まります。

レビューには少し時間がかかります。完了すると、変更されたファイルごとにCodeRabbitの指摘が表示されます。

## 指摘の種類を読む

レビュー結果には、ファイルごとにコメントが並びます。指摘には、たとえば次のような種類があります。

- Potential Issue: バグ、セキュリティ、仕様漏れなど、対応を検討すべき問題の可能性
- NITPICKS: 命名、表現、軽微な読みやすさなど、優先度の低い指摘

まずは Potential Issue を優先して読みます。認証機能のようにセキュリティに関わる変更では、パスワード、Cookie、セッション、認可漏れに関する指摘が出た場合、特に注意して確認します。

一方で、NITPICKSは必ず直すものではありません。プロジェクトの方針に合っているか、今直す価値があるかを判断します。

## ファイル上でインラインコメントを確認する

Reviewsタブで指摘をクリックすると、対象ファイルのビューワーが開きます。該当する行には、CodeRabbitのコメントがインラインで表示されます。

この画面では、差分を見ながら「どの行に対する指摘なのか」「なぜ問題だと言っているのか」を確認できます。指摘文だけを読むのではなく、必ず周辺コードも見てください。AIの指摘が正しいかどうかは、現在のコードと仕様に照らして判断します。

## 指摘に対して取れるアクション

インラインコメントには、指摘に対するアクションが表示されます。主なアクションは次のとおりです。

| アクション | 使いどころ |
| --- | --- |
| Apply suggested change | CodeRabbitが提示した小さな修正を、その場で適用する |
| Ignore | このプロジェクトでは対応不要だと判断した指摘を無視する |
| Fix with AI | 修正に必要な指示を、設定済みのAIコーディングエージェントに送る |
| Collapse all | 展開されているコメントをまとめて閉じる |
| Provide feedback | CodeRabbitのコメント自体にフィードバックを返す |

Apply suggested change は便利ですが、適用前に必ず差分を読みます。提案された修正が、意図した仕様や既存コードの設計に合っているとは限りません。

Ignore は、指摘が不要な場合に使います。たとえば、教材用の簡略化として意図的に省いた処理や、別の章で扱う予定の改善は、ここで無視しても構いません。ただし、セキュリティやデータ破壊に関わる指摘を無視する場合は、理由を説明できる状態にしておきます。

## Fix with AIを使う

Fix with AI を選ぶと、その指摘を修正するためのAIプロンプトが、あらかじめ設定してあるAIコーディングエージェントに送信されます。

設定したAgent Typeによって、Claude Code、Codex CLI、GitHub Copilot系の拡張、クリップボードなど、送信先は変わります。エージェントが起動すると、CodeRabbitの指摘内容、対象ファイル、期待される修正方針を含むプロンプトが渡されます。

ここで大切なのは、AIに直させたあとで終わりにしないことです。修正後は、必ず次を確認します。

- 指摘が本当に解消されているか
- 余計なファイルや大きすぎる変更が入っていないか
- 認証の前提が壊れていないか
- ビルドとテストが通るか

認証機能の変更なら、少なくとも `npm run build` と `npm test` を実行し、ログイン、ログアウト、未ログイン時のAPI保護が壊れていないことを確認します。

## コメントにフィードバックを返す

Provide feedback から、CodeRabbitのコメントに対してフィードバックを返せます。

返せるフィードバックは次のとおりです。

- Comment is helpful
- Comment is not true
- Comment is poorly formatted
- Comment is attached to the wrong line(s)
- Comment suggestion is invalid

正しい指摘には Comment is helpful を返します。誤検知だった場合は Comment is not true、提案コードが壊れている場合は Comment suggestion is invalid を選びます。

このフィードバックは、単なる評価ではなく、「AIレビューのどこが役に立ち、どこが外れていたか」を自分で判断する練習にもなります。

## コメント一覧から確認する

CodeRabbitのレビュー結果は、Reviewsタブだけでなく、IDEのコメント一覧にも表示されます。

VS Codeのコメントビューを開くと、ファイルごと、行ごとに付いたコメントを一覧できます。複数の指摘を順番に処理したいときや、まだ対応していないコメントを探すときに便利です。

## 対応後に再確認する

指摘に対応したら、もう一度差分を確認します。

```bash
git diff
npm run build
npm test
```

必要に応じて、CodeRabbitのReviewsタブから再度レビューを実行します。IDEレビューはPRを作る前に使えるので、ここで明らかな問題を減らしておくと、PRレビューではより大きな設計や仕様の確認に集中しやすくなります。

## ここまでのまとめ

この章では、VS Code上でCodeRabbitのIDEレビューを体験しました。

- CodeRabbit拡張を入れ、Reviewsタブから Review all changes を実行した
- ファイルごとの Potential Issue や NITPICKS を確認した
- 指摘をクリックし、ファイル上のインラインコメントとして読んだ
- Apply suggested change、Ignore、Fix with AI、Provide feedback などのアクションを確認した
- IDEのコメント一覧からもレビュー結果を確認できることを見た

IDEレビューは、PRを出す前のセルフチェックとして使えます。エディタの中で差分を確認し、必要な指摘だけを選んで対応する流れを押さえておきます。
