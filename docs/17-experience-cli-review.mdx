# CLIレビューを体験する

## この章の目的

[CLIをインストールする](cli-installation)でセットアップしたCodeRabbitプラグインまたはSkillsを使い、AIコーディングエージェントからレビューを受ける流れを体験します。

前章では、Bookmark Demoにフォルダ分け機能を追加しました。この章では、その変更を題材にして、CodeRabbit CLIがどのような指摘を出すか、指摘をどう読み、どう対応するかを確認します。

## CLIレビューを開始する

まず、`bookmark-demo` フォルダにいることを確認します。

```bash
pwd
git status
```

次に、CLIの状態を確認します。

```bash
cr doctor
```

問題なければ、レビューを実行します。

AIコーディングエージェントに、次のように依頼します。

```prompt
CodeRabbitで現在の変更をレビューしてください。
出た指摘が今のコードに対して妥当かを確認し、妥当なものは修正してください。

修正後、次の一覧を表示してください。
- CodeRabbitの指摘
- 妥当かどうかの判断
- 修正した内容、または修正しなかった理由
```

CodexのCodeRabbitプラグインやCodeRabbit Skillsでは、自然文の依頼をもとにエージェントがCodeRabbit CLIを呼び出します。レビューには時間がかかることがあります。完了すると、エージェントがCodeRabbitの指摘を確認し、妥当なものから修正します。

## レビュー結果と修正内容を確認する

CodeRabbitのレビュー結果には、ファイル名、該当箇所、指摘内容、修正案が含まれます。

エージェントの作業が終わったら、指摘ごとに次を確認します。

- 指摘内容
- 妥当かどうかの判断
- 修正した内容、または修正しなかった理由

たとえば、実行結果は次のようになります。

````text
npm run build / npm test ともに成功。テストは37件すべて合格。
CodeRabbitレビュー結果: 9件

| # | CodeRabbitの指摘 | 重大度 | 妥当性の判断 | 対応 |
| --- | --- | --- | --- | --- |
| 1 | `CreateFolderRequest` / `UpdateFolderRequest` にzodスキーマを追加する | major | 非妥当。既存コードでzodは使っておらず、入力確認はサーバー側の既存処理に合わせて実装済み | 修正なし |
| 2 | マイグレーションにdown処理がない | minor | 非妥当。既存のマイグレーションは前進適用のみで、過去のファイルにもdown処理はない | 修正なし |
| 3 | フォルダ操作ボタンに`:focus`指定がない | critical | 非妥当。`outline: none`を指定しておらず、ブラウザ標準のフォーカス表示が残っている | 修正なし |
| 4 | フォルダ名に空文字を防ぐCHECK制約を追加する | minor | 妥当。アプリ側でも確認しているが、DB側の防御として有効 | `CHECK (length(trim(name)) > 0)` を追加 |
| 5 | テストでブックマーク作成処理を`await`していない | critical | 非妥当。対象のDB APIは同期処理で、既存テストも同じ書き方 | 修正なし |
````

この例では、9件のうち実際に修正したのはDBのCHECK制約だけです。残りは、既存コードの方針や実装事実と照らして非妥当と判断し、修正していません。

CodeRabbitの指摘は最終判断ではありません。指摘された箇所の周辺コードを読み、今回の仕様に照らして本当に直すべきか判断します。

## 直近の結果を再表示する

レビュー結果をもう一度読みたい場合は、直近の結果を再表示できます。

```bash
cr review findings
```

修正中にターミナルの表示が流れてしまったときや、AIエージェントに前回の結果を再確認させたいときに使えます。

## ここまでのまとめ

この章では、AIコーディングエージェントからCodeRabbit CLIレビューを呼び出す流れを体験しました。

- `cr doctor` でCLIの状態を確認した
- CodeRabbitプラグインまたはSkillsからレビューを実行した
- フォルダ分け機能に対する指摘を読み、重要度を判断した
- 必要な指摘に対応し、`npm run build` と `npm test` で確認した
- AIコーディングエージェントからCLIレビューを呼び出す流れを確認した

CLIレビューは、コミット前のセルフチェックとして使えます。変更を小さいうちに確認し、必要な修正だけを選んで対応する習慣を作りやすくなります。
